# Semantic TextNavigator

Локальный прототип для специалиста по закупкам: загрузка TXT, действующие суммы и сроки на выбранную дату, точные цитаты и несогласованные предложения. Смысловой поиск использует настоящую `intfloat/multilingual-e5-small`; применимость условий проверяется явными правилами. Ответы и номера договоров в коде приложения не зашиты.

## Установка и запуск

Нужен Python 3.12. Проверено на macOS ARM64 с CPU. Установка библиотек и первая загрузка модели требуют интернета; платный аккаунт, API-ключ и GPU не нужны. Веса модели занимают около 470 МБ, библиотеки и кеш требуют дополнительного места. Для спокойной работы желательно 4 ГБ свободной оперативной памяти.

В терминале перейдите в распакованную папку `textnavigator`:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m textnavigator.app
```

В Windows: `py -3.12 -m venv .venv`, затем `.venv\Scripts\activate`; следующие команды те же.

Откройте **http://127.0.0.1:8765**. Нажмите «Открыть учебный комплект» либо «Выбрать TXT», дождитесь готовности модели и нажмите «Проверить условия». Сервер слушает только локальный адрес. Остановка — Ctrl+C. Другой порт: `python -m textnavigator.app --port 8766`.

Модель скачивается в `.model-cache`. После успешной загрузки можно работать без сети:

```bash
TEXTNAV_OFFLINE=1 python -m textnavigator.app
```

В PowerShell сначала `$env:TEXTNAV_OFFLINE="1"`. Путь к готовому кешу можно задать переменной `TEXTNAV_MODEL_CACHE`. Скачиваются только файлы модели; тексты документов обрабатываются локально. Версия модели закреплена на commit `614241f622f53c4eeff9890bdc4f31cfecc418b3`, удаленный код модели не исполняется.

Если загрузка модели недоступна, есть явно ограниченный режим: `python -m textnavigator.app --rules-only`; отметьте «Только правила» в интерфейсе. В нем нет embeddings и смыслового поиска, это показано в результате. Подмена модели заглушкой отсутствует.

## Примеры использования

Дата проверки учебного комплекта — **10.03.2026**, независимо от сегодняшней даты.

1. Срок STN-101: нажмите `30.04.2026` в таблице. Справа — цитата из подписанного допсоглашения, ниже — подтверждение подписи, вступления в силу и прежний срок `15.04.2026`.
2. Сумма STN-102 — `840 000 ₽`. Аванс `252 000 ₽` не добавляется к стоимости.
3. Сумма STN-103 — «Нет данных»: спецификации нет, бюджетный лимит не принимается за цену договора. Нажатие показывает соответствующий пункт.
4. «Поставка раньше 01.04.2026» → «Применить»: остается STN-102 со сроком `20.03.2026`, ниже — несогласованное предложение `27.03.2026`. Граница фильтра строгая.
5. Поиск «ответственность за задержку поставки» находит близкие по смыслу пункты. Это список источников, а не автоматически сформированный юридический ответ.
6. Измените числовую сумму в TXT, добавьте договор аналогичного формата с новым номером и загрузите комплект заново. Новая загрузка заменяет предыдущую; изменение даты требует повторной проверки.

## Проверки

```bash
python -m unittest discover -s tests -v
TEST_EMBEDDINGS=1 TEXTNAV_OFFLINE=1 python -m unittest discover -s tests -v
```

Первая команда проверяет правила и API без загрузки модели. Вторая дополнительно запускает настоящую модель из кеша: размерность и нормализацию векторов, попадание четырех нужных источников в top-3 и результат полного гибридного конвейера. В PowerShell задайте переменные окружения отдельными командами. Изменения суммы, новый договор, порядок и имена файлов, отсутствующие значения, статус подписи, будущие даты, конфликты и точность цитат проверяются отдельными тестами.

Результаты фактического прогона и затраченное время находятся в [VALIDATION.md](VALIDATION.md). Полный набор установленных версий для воспроизведения проверенного окружения — [requirements-lock.txt](requirements-lock.txt).

## Краткая продуктовая и техническая записка

**Пользователь и польза.** Специалист по закупкам сверяет сумму и срок поставки, проверяет основание одним нажатием и видит предложения, которые еще нельзя считать обязательствами. Приоритет — правильное условие и проверяемый источник. Прототип не утверждает подлинность подписей: он читает текстовое поле статуса учебного документа.

**Пять вопросов клиенту.** Какие форматы и варианты формулировок встречаются чаще всего? Кто и как подтверждает факт подписания и вступления в силу? Как разрешаются противоречия между несколькими допсоглашениями? Какие действия закупщика должен ускорить результат проверки? Как устроены права доступа и допустимо ли локальное хранение извлеченных данных?

**Допущения.** Один основной договор на номер; рубли; абсолютные даты `ДД.ММ.ГГГГ`; поля и формулировки близки к учебному комплекту. Стороны указываются после `Поставщик:`. Изменение применяется отдельно к каждому полю, только при подтвержденной подписи обеих сторон и наступившей дате вступления в силу. При одинаковой дате двух изменений одного поля приоритет не угадывается. Имена файлов, дата загрузки и величина semantic score не задают юридический приоритет.

**Две метрики.** (1) Доля правильно определенных суммы/срока вместе с правильным статусом и источником на отложенном наборе договоров; отдельно учитывать ошибочно уверенные ответы. (2) Медианное время от загрузки комплекта до подтвержденного пользователем ответа на вопрос, в сравнении с ручным просмотром. Результаты на четырех учебных источниках не доказывают качество на реальных договорах.

**Архитектура.** Браузер → локальный Flask → разбиение текста на пункты с исходными смещениями → E5 и поиск кандидатов → извлечение значений и разрешение изменений → таблица и цитаты. Документы и векторы находятся в оперативной памяти процесса. Один процесс обслуживает один комплект: отдельные пользовательские сессии отсутствуют. После перезапуска сервера комплект надо загрузить заново.

**Три решения и компромиссы.** (1) Готовая многоязычная E5 без дообучения дает смысловой поиск на CPU, но требует загрузки весов и не гарантирует понимание отрицаний. Используются префиксы `query:`/`passage:` и нормализованные векторы. (2) Явные правила дают воспроизводимые значения и объяснимую применимость, но поддерживают ограниченный набор формулировок. Семантические кандидаты объединяются с полным проходом по явным пунктам: пропуск top-3 не должен скрыть условие. (3) Векторы в памяти и линейный поиск сокращают зависимости, но не подходят для большого многопользовательского архива.

**При 100 000 документов и наличии прав.** Фоновая очередь индексации, хранение оригиналов и версий, структурированные условия и журнал происхождения в БД, векторный индекс с фильтрацией по доступным документам до выдачи. Проверка прав повторяется при открытии цитаты; кеши разделяются по пользователям/правам и инвалидируются при изменениях. Нужны отдельные сессии, аудит, инкрементальные пересчеты и измерение задержек и качества на репрезентативных данных.

**Три следующих улучшения по приоритету.** (1) Расширить тестовый корпус, разметить сложные случаи и измерить ошибки уверенных ответов. (2) Добавить извлечение ставки неустойки и других полей через тот же контракт «значение — статус — источник». (3) Добавить версии документов, рабочее место ручного разрешения конфликтов и права доступа. Дообучать embeddings стоит после измеренного недостатка поиска и появления размеченных примеров.

## Отчет о вайбкодинге

Использован Codex: чтение задания и шести TXT, выбор архитектуры, написание кода, тестов и инструкции, запуск настоящей модели и проверка браузерного сценария. Это описание работы агента; время самостоятельного изучения кода кандидатом в него не входит.

Два характерных реальных запроса пользователя: «так а насколько нам сложно использовать, найти либо обучить небольшую embed модель?» и «да я согласен, embed плюс явные правила, будет ок». По ним выбрана готовая локальная модель, затем реализован гибридный прототип. Полная переписка не требуется для запуска.

**Ошибка и исправление.** Первая версия правила срока искала `до` без границы слова. Оно срабатывало внутри «оборудования», поэтому описание предмета поставки ошибочно считалось неоднозначным сроком. Прогон на исходном STN-101 выявил ошибку; добавлены границы слова и регрессионная проверка результата. Вывод: даже простые правила требуют проверки отрицательных примеров; embeddings не заменяют эти проверки.

**Технический сбой.** Первая загрузка весов через Xet зависла без прогресса. Использован обычный HTTPS-путь (`HF_HUB_DISABLE_XET=1`), затем запущены интеграционные проверки. Этот параметр задается приложением и может быть переопределен окружением.

## Известные ограничения

- Только TXT в UTF-8, до 30 файлов, до 1 МБ каждый и 4 МБ на запрос. PDF, DOCX, OCR и проверка электронных подписей отсутствуют.
- Каждый непустой ряд исходного TXT считается пунктом; произвольный перенос одной фразы на несколько строк может потребовать ручной проверки. Цитата хранит исходные символы и номер строки. BOM убирается при чтении.
- E5 обрабатывает первые 512 токенов пункта; извлечение правилами читает весь пункт. Длинные и сложные документы нужно разбивать более аккуратно.
- Поддерживаются рублевые суммы, записанные цифрами, и абсолютные даты. Рассрочка, этапы поставки, относительные сроки, валюты, отмены и сложные ссылки требуют расширения правил. Расхождение суммы цифрами и прописью автоматически не проверяется.
- При нераспознанной формулировке возможен пропуск. Метка «Нет данных» означает отсутствие распознанного значения в предоставленном тексте, а не доказательство отсутствия условия во всех документах. Явные неоднозначности показываются как «Требует проверки».
- Известные проекты и письма не меняют условия даже при высоком сходстве. Для связанного допсоглашения с неясным статусом уверенное значение не показывается. Неоднозначные ссылки и отсутствующие исходные договоры выводятся в предупреждения.
- Это локальный однопользовательский прототип с Flask development server, без промышленного развертывания и произвольного чата. Секретов и ключей в проекте нет.

Модель и ее лицензия MIT: [карточка multilingual-e5-small](https://huggingface.co/intfloat/multilingual-e5-small). Документация: [Sentence Transformers](https://www.sbert.net/docs/sentence_transformer/usage/semantic_textual_similarity.html).
